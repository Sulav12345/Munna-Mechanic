![This diagram depicts the database schema and data relationships for an On-Demand Mechanic/Roadside Assistance Platform. It shows six main entities (tables) with their attributes, primary keys (PK), foreign keys (FK), and cardinalities:   USER: Stores customer information (user_id [PK], name, phone_no, email_id, current_latitude, current_longitude).   VEHICLE: Stores user vehicle details (vehicle_id [PK], make, model, license_plate, user_id [FK]). A 1-to-N (One-to-Many) relationship links USER to VEHICLE ("owns").   SERVICE_REQUEST: Acts as the central transaction table (request_id [PK], description, status, user_id [FK], vehicle_id [FK], mechanic_id [FK], timestamp, request_location latitude and longitude, vendor_id [FK]). It links to USER ("makes"), VEHICLE ("is involved in"), VENDOR ("managed by"), and MECHANIC ("is assigned to").   VENDOR: Contains shop/business owner information (vendor_id [PK], proprietor, phone_number, location, email_id). A 1-to-N relationship connects VENDOR to MECHANIC ("employs").   MECHANIC: Contains field mechanic profiles (mechanic_id [PK], name, phone_number, email_id, current_latitude, current_longitude, vendor_id [FK]).   ADMIN: Standalone management entity (admin_id [PK], name, email_id) used for system oversight.](er.jpg)
